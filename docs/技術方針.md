## 2. 詳細方針（2-1〜2-5 は 2026-10-01 に承認済み）

### 2-1. ディレクトリ構成

リポジトリ直下＝Web ルート（既存の決定）を維持する。Web から直接開く画面（PHP）だけを直下に置き、内部のコードや設定は別のフォルダに入れて、Web からは見えないようにする。

```
/                       ← Web ルート（リポジトリ直下）
├── index.php           メイン画面（リポジトリ直下に置く）
├── login.php           ログイン
├── logout.php          ログアウト
├── records/            記録表示・修正申請（index.php ほか）
├── approvals/          承認（index.php ほか）
├── admin/              システム管理者：アカウント作成・部署・勤務設定
├── api/                出退勤・申請などの API（JSON）
├── css/  js/           スタイルと JavaScript
├── src/                内部コード（認証・勤怠・申請・権限・DB 接続など）。Web から直接アクセス不可
├── templates/          画面の共通部品（ヘッダー等）。Web から直接アクセス不可
└── tests/              自動テスト。Web から直接アクセス不可
```

- 内部のコード・テスト・Git の管理ファイル等を Web から見えないようにする設定は、`.htaccess` ではなく **Apache の設定ファイル**（[apache/attendance.conf](./apache/attendance.conf)）で行う。WSL の Apache は `AllowOverride None` のため `.htaccess` が効かない。設定の適用手順は [Apache設定手順書.md](./Apache設定手順書.md)。
- この設定が無いと、`http://localhost/attendance/.git/config` や `docs/` が Web から見えてしまう（Apache で実際に確認済み）。

- `index.php` はリポジトリ直下（依頼者の指示）。ファイルが多くなる機能は、フォルダを作って整理する（上の `records/`、`approvals/`、`admin/`）。
- 画面の数と、1画面あたりのファイル数は、少なく保つ。画面ごとに1つの PHP が、表示（GET）と更新（POST）を処理する（[PHPコーディング方針.md](./PHPコーディング方針.md) 3-3）。
- この構成は案。画面設計（画面遷移）を詰める段階で、見直す。

### 2-2. DB の接続情報（2026-10-13 変更。D-045）

- DB の接続情報（DB 名・ユーザー・パスワード）は、既存コード（`phpKakeibo` の `dbconnect.php`）と同じく、**`src/dbconnect.php` に直接書く（ハードコーディング）**。学習用のプロジェクトで、外部に公開しないため（依頼者の判断）。
- Web ルートの外の設定ファイル（`/var/www/attendance_private/config.php`）は、作らない（当初の案は取りやめ）。
- 注意点：
  - パスワードは、リポジトリ（GitHub、非公開）と、その履歴に残る。**リポジトリを公開しない**。**他で使っているパスワードを使わない**（この DB 専用にする）。
  - `src/` は、Apache の設定で Web から見えない（D-039。Claude の検証環境で確認済み）。
  - 将来、外部に公開する場合は、接続情報をリポジトリの外に移す（Web ルートの外の設定ファイル、または環境変数）。

### 2-3. セキュリティ

| 対象 | 対策 |
| --- | --- |
| SQL インジェクション | すべての SQL に PDO のプリペアドステートメントを使う（文字列連結をしない） |
| パスワード | `password_hash()`／`password_verify()`（登録済みの形式と同じ） |
| セッション | ログイン成功時に `session_regenerate_id(true)`。Cookie は `HttpOnly`、`SameSite=Lax`。一定時間で期限切れ |
| CSRF | 更新系（POST）はすべてトークンを検証する |
| XSS | 画面に出力する値は `htmlspecialchars()` でエスケープする |
| 認可 | 画面・API ごとに、権限（社員／管理者／システム管理者）と承認範囲（`approval_scope`）をサーバー側で必ず確認する。BR-003（ログイン済みのみ）もサーバーで強制する |
| 入力チェック | 画面側のチェックとは別に、サーバー側でも必ず検証する（引継ぎ資料の注意点どおり） |
| 時刻 | `date_default_timezone_set('Asia/Tokyo')`、DB 接続ごとに `SET time_zone='+09:00'`（BR-004） |
| ログイン失敗の対策 | 今回は含めない（P-8 のとおり）。必要になったら別途検討 |

### 2-6. CSS・フォント・アイコン（2026-10-01 依頼者の回答を受けて追加）

| 項目 | 方針 |
| --- | --- |
| Bootstrap | **使わない**。Bootstrap は、ボタンや表などの見た目の部品をまとめた「CSS フレームワーク」で、Google Material Icons（アイコン）とは別のもの。画面モックは独自の配色・形（Figma の変数 24 個）なので、自前の CSS で合わせる |
| リセット CSS | `ress` を最初に読み込む（既存コード `phpKakeibo/index.php` でも使っているものと同じ）。`<link rel="stylesheet" href="https://unpkg.com/ress@5.0.2/dist/ress.min.css">` を、自前の CSS より前に置く |
| フォント | 画面モックの指定どおり **IBM Plex Sans JP**（Google Fonts）。`font-family: "IBM Plex Sans JP", "Hiragino Sans", "Yu Gothic", sans-serif` |
| アイコン | **Google の Material Symbols**（Outlined）を使う。画面モックは、メニュー・閉じる・前後の矢印・時計をインライン SVG で描いているが、同じ意味の Material Symbols（`menu`、`close`、`chevron_left`、`chevron_right`、`schedule`、`logout` など）に置き換える。アイコンだけのボタンには `aria-label` を付ける |
| 外部の読み込み | `ress`（unpkg）、フォントとアイコン（Google Fonts）は CDN から読み込む。**社内ネットワークから、これらの CDN に接続できることが前提**。接続できない場合、見た目が崩れる（フォントは代替フォントになり、アイコンは表示されない）。実装 PR 1 の前に、WSL のブラウザで接続できることを確認する |

アイコンの読み込みと使い方（Google Fonts の公式の形式）：

```html
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Material+Symbols+Outlined:opsz,wght,FILL,GRAD@24,400,0,0">
<span class="material-symbols-outlined" aria-hidden="true">schedule</span>
```
