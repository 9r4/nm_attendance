## 2. 案（要承認）

### 2-1. ディレクトリ構成

リポジトリ直下＝Web ルート（既存の決定）を維持する。Web から直接開く画面（PHP）だけを直下に置き、内部のコードや設定は別のフォルダに入れて、Web からは見えないようにする。

```
/                       ← Web ルート（リポジトリ直下）
├── index.php           メイン画面（リポジトリ直下に置く）
├── login.php           ログイン
├── logout.php          ログアウト
├── records/            記録表示・修正申請（index.php ほか）
├── approvals/          承認（index.php ほか）
├── admin/              システム管理者：アカウント作成・部署・勤務設定
├── api/                出退勤・申請などの API（JSON）
├── css/  js/           スタイルと JavaScript
├── src/                内部コード（認証・勤怠・申請・権限・DB 接続など）。Web から直接アクセス不可
├── templates/          画面の共通部品（ヘッダー等）。Web から直接アクセス不可
├── tests/              自動テスト。Web から直接アクセス不可
└── .htaccess           src/・templates/・tests/ などへのアクセスを拒否（Apache）
```

- `index.php` はリポジトリ直下（依頼者の指示）。ファイルが多くなる機能は、フォルダを作って整理する（上の `records/`、`approvals/`、`admin/`）。
- 画面の数と、1画面あたりのファイル数は、少なく保つ。画面ごとに1つの PHP が、表示（GET）と更新（POST）を処理する（[PHPコーディング方針.md](./PHPコーディング方針.md) 3-3）。
- この構成は案。画面設計（画面遷移）を詰める段階で、見直す。

### 2-2. 設定（DB のパスワード）の置き場所

- DB 接続情報（ユーザー・パスワード）は、**リポジトリにも Web ルートにも置かない**（書き方の見本は [PHPコーディング方針.md](./PHPコーディング方針.md) 4章）。Web ルートの外 `/var/www/attendance_private/config.php` に置く（WSL に手動で作成。権限は所有者と Apache のみ読める 640）。
- リポジトリには、設定の**雛形**（`config.sample.php`、値はダミー）だけを置く。
- 理由：リポジトリ直下が Web ルートで、設定ファイルが Web から見えたり、Git に入ったりする事故を防ぐため。

### 2-3. セキュリティ

| 対象 | 対策 |
| --- | --- |
| SQL インジェクション | すべての SQL に PDO のプリペアドステートメントを使う（文字列連結をしない） |
| パスワード | `password_hash()`／`password_verify()`（登録済みの形式と同じ） |
| セッション | ログイン成功時に `session_regenerate_id(true)`。Cookie は `HttpOnly`、`SameSite=Lax`。一定時間で期限切れ |
| CSRF | 更新系（POST）はすべてトークンを検証する |
| XSS | 画面に出力する値は `htmlspecialchars()` でエスケープする |
| 認可 | 画面・API ごとに、権限（社員／管理者／システム管理者）と承認範囲（`approval_scope`）をサーバー側で必ず確認する。BR-003（ログイン済みのみ）もサーバーで強制する |
| 入力チェック | 画面側のチェックとは別に、サーバー側でも必ず検証する（引継ぎ資料の注意点どおり） |
| 時刻 | `date_default_timezone_set('Asia/Tokyo')`、DB 接続ごとに `SET time_zone='+09:00'`（BR-004） |
| ログイン失敗の対策 | 今回は含めない（P-8 のとおり）。必要になったら別途検討 |

5. WSL で、次のコマンドを実行して、結果を教えてほしい（PHP を Apache がどう動かしているか、`.htaccess` が有効かを確認する）。

**【ターミナルで実行】**

```bash
apache2ctl -M 2>/dev/null | grep -E "php|rewrite|headers"
```

**【ターミナルで実行】**

```bash
grep -rn "AllowOverride" /etc/apache2/ | grep -v "^.*:#"
```

**【ターミナルで実行】**

```bash
ls /var/www/
```

- 1つ目：PHP を実行するモジュール（`php`）と、`rewrite`・`headers` が表示されるか。
- 2つ目：`/var/www/` の設定で `AllowOverride All` になっているか（`.htaccess` の有効化に必要）。
- 3つ目：Web ルートの外 `/var/www/attendance_private/` を作る場所（`/var/www/` が書き込み可能か）の確認。
