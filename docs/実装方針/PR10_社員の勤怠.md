# 実装 PR 10：社員の勤怠（管理者が、対象社員の一覧と、1人ずつの記録を見る）

状態: **承認済み（2026-10-26。D-070）**。作業ブランチ `claude/pr10-members` で実装する。

## 1. 目的

- 管理者（`manager`）が、**対象社員の一覧**を、**今日の勤怠**（状態・出勤・退勤・休憩）と一緒に見られる（2026-10-26 依頼者の依頼）。
- 一覧の「**詳細**」を押すと、その社員の**今日以外の日**の記録も、記録表示と同じ月カレンダーで見られる。
- [決定事項.md](../決定事項.md) の「未決定」にある「**他ユーザの記録確認**」のうち、管理者が見る分にあたる（社員どうしで見合う機能は作らない）。
- 依頼者が、**LEFT JOIN の結ぶ条件（ON）に値の条件を入れる**書き方を覚える（WHERE に入れると、打刻していない社員が一覧から消える）。

## 2. 画面と動き

画面名は「**社員の勤怠**」。URL は `members/`（一覧）と `members/detail.php`（詳細）。使えるのは**管理者だけ**（社員・システム管理者は 403）。ハンバーガーメニューの「承認」の下に「社員の勤怠」（管理者のみ）を追加する。

### 2-1. 一覧（`members/`）

| 部分 | 内容 |
| --- | --- |
| 見出し | 「社員の勤怠」と、今日の日付（例：2026年10月26日（月））。 |
| 対象社員 | **承認範囲と同じ**：承認範囲が「部署」の管理者は自分の部署の社員、「全社」の管理者は全社員（D-025）。**自分は出さない**（自分の分は記録表示で見る）。**在籍中の社員だけ**（退職は出さない）。管理者（他の管理者）も社員なので出る |
| 並び順 | 部署（部署の作成順）→ 社員コードの順 |
| 1人の内容 | 社員コード、氏名、部署、**状態**（未出勤・勤務中・休憩中・退勤済み。メイン画面と同じ名前と色）、出勤、退勤、休憩、労働時間（退勤済みの人だけ。ほかは `--`）、「**詳細**」ボタン |
| 対象社員がいないとき | 「対象の社員はいません。」 |
| PC とスマホ | PC は表（1行に1人）、画面の幅が 768px 未満ではカード型（承認画面と同じ切り替え。D-052） |

- 今日の勤怠は、画面を開いた（読み込み直した）時点のもの（自動では更新しない）。
- 時刻・状態の作り方は、メイン画面・記録表示と同じ関数を使う（`attendanceView()`・`dailyWorkMinutes()`）。

### 2-2. 詳細（`members/detail.php?id=2025001&month=2026-09`）

| 部分 | 内容 |
| --- | --- |
| 見出し | 「＜ 社員の勤怠」（一覧へ戻るリンク）、社員の氏名・社員コード・部署（例：山田 太郎（2025001・営業部）） |

| 日付を押したとき | その日の記録（出勤・退勤・休憩・労働時間）と、申請の一覧（変わった項目だけ「変更前 → 申請値」、理由、却下コメント）を表示する |

- **記録表示の画面の部品を、2つの画面で使い回す**：記録表示（`records/index.php`）のカレンダーと日付のウィンドウの HTML を `templates/calendar.php` に移し、記録表示と詳細の両方から読み込む。記録表示の見た目と動きは変えない（PR 4・5・#7 の確認を流し直して確かめる）。
- `js/records.js` に「**見るだけ**」の動き（`data-readonly`）を足す。見るだけのときは、申請ウィンドウ・取り消しのボタン・申請中の案内を出さず、記録も申請も無い日を押したときは「記録はありません。」のウィンドウを出す。
- 見るだけの判断は、サーバーでも行う（詳細の画面には、申請ウィンドウの HTML と申請の API の URL を出さない。申請の API は、今までどおり自分の分しか受け付けない）。
- 見てよい社員かの判断 `canViewMember()` を `src/members.php`（新規）に作る。一覧の取得と同じ条件（管理者、自分でない、在籍中、承認範囲）を、詳細でも確かめる。

## 5. 依頼者が書くもの（仕様）

値は `bindValue` で渡す（D-060）。部署 ID は数値なので `PDO::PARAM_INT`、それ以外は `PDO::PARAM_STR`。関数の `{` は関数名と同じ行（D-056）。枠には、処理の流れのコメントを書いておく（D-054）。

### 5-1. `fetchMemberAttendances()`（一覧：対象社員と、その日の勤怠）

| 項目 | 内容 |
| --- | --- |
| 関数 | `function fetchMemberAttendances(PDO $pdo, string $managerId, ?int $departmentId, string $workDate): array {` |
| 引数 | `$managerId`：見ている管理者の社員 ID（自分を除くため）。`$departmentId`：承認範囲が「部署」なら管理者の部署 ID、「全社」なら null（承認の `fetchPendingRequests()` と同じ）。`$workDate`：今日（'2026-10-26'） |
| SQL | 社員 `employees e` に部署 `departments d` を JOIN し、勤怠 `attendances a` を **LEFT JOIN**（打刻していない社員も出すため）。**LEFT JOIN の結ぶ条件は `a.employee_id = e.employee_id AND a.work_date = :work_date`**。条件：`e.employment_status = 'active' AND e.employee_id <> :manager_id`。`$departmentId` が null でなければ `AND e.department_id = :department_id` を付け足す。並び順：`ORDER BY d.id, e.employee_id` |
| 取得する列 | `e.employee_id, e.name, d.name AS department_name, a.check_in_at, a.check_out_at, a.break_start_at, a.break_end_at` |
| 戻り値 | 行の配列（対象社員がいなければ `[]`）。打刻していない社員は、勤怠の4列が null |
| ポイント | **日付の条件は WHERE ではなく ON に書く**。WHERE に `a.work_date = :work_date` と書くと、勤怠の行が無い社員（a の列が NULL）が条件に合わず、一覧から消える（LEFT JOIN にした意味が無くなる）。ON に書けば、「その日の勤怠があれば結ぶ、無ければ NULL」になる |

### 5-2. `fetchEmployeeProfile()` の変更

- SELECT する列に `e.employment_status` を追加する（詳細の画面で、退職した社員を出さないための判断に使う）。

### 5-3. 確認方法（依頼者の WSL）

テストデータ：2025001（山田・営業部・社員）、2025002（佐藤・営業部・管理者・承認範囲は部署）、2025003（鈴木・開発部・管理者・承認範囲は全社）、2025004（高橋・開発部・社員・ログイン不可）。

1. 2025001 でログインして出勤を押す（ログアウトする）。
2. 2025002 でログイン →「≡」→「社員の勤怠」→ 山田さんだけが出て、状態が「勤務中」、出勤の時刻が出る（自分（佐藤）と開発部の人は出ない）。
3. 山田さんの「詳細」→ 記録表示と同じカレンダーで、山田さんの記録が出る。前の月にも移れる。日付を押すと、その日の記録と申請が出て、「修正」「申請する」「取り消す」のボタンは出ない。
4. 2025003（全社）でログイン →「社員の勤怠」→ 山田・佐藤・高橋さんが出る（自分は出ない。高橋さんはログイン不可だが在籍中なので出る）。打刻していない人は「未出勤」。PR 7 の確認で作ったアカウントがあれば、それも出る（退職にしたものは出ない）。
5. 2025002 で、URL を `members/detail.php?id=2025003` に書き換えて開く →「この社員の勤怠は表示できません。」
6. 2025001（社員）で `members/` を開くと、使えない（403）。メニューにも「社員の勤怠」が出ない。
