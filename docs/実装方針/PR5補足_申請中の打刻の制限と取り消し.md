# 実装 PR 5 の補足：申請中の打刻の制限と、申請の取り消し

状態: **PR #7 を作成、依頼者の承諾待ち**（2026-10-15）。作業ブランチ `claude/fix-pending-punch`。依頼者の指摘（PR 6 の方針の確認のとき）を受けて追加し、依頼者の了承（「この件についてはあなたが修正してしまっていい」）を得て、DB の関数も含めて Claude が実装した（D-063）。

## 1. 問題

今日の分の修正・新規登録を申請したあとに打刻すると、承認されたときに申請の値で上書きされ、押した打刻が消える。例：20 時に「退勤 19:00」で申請したあと、誤って退勤を押すと、勤怠は「退勤 20:00」になり、承認で「19:00」に戻る。

## 2. 対応

| 項目 | 内容 |
| --- | --- |
| 打刻の制限 | 今日の分の修正・新規登録が申請中の間は、メイン画面の出勤・退勤・休憩開始・休憩終了をすべて押せなくする（サーバーでも止める）。案内「本日の修正申請が申請中のため、打刻できません。打刻する場合は、記録表示で申請を取り消してください。」と、記録表示へのリンクを出す |
| 止めないもの | 残業の申請中（退勤を押し直しても、退勤は後ろにずれるだけで、残業の申請の範囲を外れない）。過去の日の申請中（打刻は今日の分だけ） |
| 申請の取り消し | 記録表示の日付のウィンドウで、申請中の申請（修正・新規登録・残業）に「取り消す」。確認のウィンドウのあと、申請を削除する（履歴に残さない。DB の変更なし）。承認・却下されたもの、ほかの人の申請は取り消せない |
| 案内の文 | 申請中の日に申請しようとしたとき、「取り消すと申請できる」ことが分かる文にした |

- `deletePendingRequest()`（`src/queries/attendance_requests.php`）は、条件に本人（`employee_id`）と申請中（`status = 'pending'`）を付けて削除し、`rowCount()` で削除できたかを返す。
