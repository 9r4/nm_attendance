### 2-3. 記録表示：申請内容の表示

- **カレンダー**：申請がある日に、状態のバッジ（申請中＝黄、承認済み＝緑、却下＝赤）。1日に複数ある場合は、申請中を優先し、無ければ最新のもの。
- **日付を押したときの表示**：その日の申請の一覧。申請ごとに、種別（修正・新規登録・残業）、状態、申請日時、**変更になる項目だけを「変更前 → 申請値」**（例：「退勤 17:30 → 18:45」「出勤 なし → 09:00」）、理由、却下コメント（PR 6 から）。

## 3. 入力のルール（サーバーで必ず確認する）

### 3-1. 修正・新規登録

| ルール | 誤りのときの表示（例） |
| --- | --- |
| 対象日：正しい日付、**入社日から今日まで**（未来の日は不可） | 「対象日は、入社日から今日までの日を指定してください。」 |
| 時刻：「時:分」の形。対象日の中の時刻（日をまたぐ時刻は入れられない） | 「時刻の形が正しくありません。」 |
| **出勤は必須** | 「出勤時刻を入力してください。」 |
| 休憩は、開始と終了の**両方を入れるか、両方とも空欄** | 「休憩は、開始と終了の両方を入力してください。」 |
| 順番：出勤 ＜ 休憩開始 ＜ 休憩終了 ＜ 退勤（入っているものどうし） | 「退勤時刻は、出勤時刻より後にしてください。」など |
| 対象日が今日のとき：今より後の時刻は不可 | 「まだ来ていない時刻は申請できません。」 |
| 今の記録と**同じ内容は不可** | 「今の記録から変更がありません。」 |
| 理由：500 文字まで | 「理由は 500 文字までにしてください。」 |
| 同じ日に、申請中の修正・新規登録がある（BR-002） | 「この日には、申請中の申請があります。承認・却下されるまで、新しい申請はできません。」 |

- 申請には、**その日の4つの時刻の全体**を保存する（変えない項目は今の値のまま。空欄は NULL）。あわせて、申請した時点の今の値を `original_*` に控える（DB設計書 P-4・P-9）。
- 修正か新規登録かは、申請した時点に、その日の記録があるかで決まる（D-051）。DB の種別は、どちらも `correction`。

| 終了時刻：「時:分」の形、標準終了時刻より後、退勤時刻まで | 「標準終了時刻（18:00）より後の時刻を指定してください。」「退勤時刻（19:30）を超える時刻は指定できません。」 |

2. **簡単残業申請の対象は本日分だけ**（2-2）：画面モック・要件（メイン画面のウィンドウ）のとおり。過去の日の残業申請は、今回は作らない（必要になったら、記録表示の日付のウィンドウに追加できる）。押せるのは、退勤が標準終了時刻より後の日だけ。
3. **入力のルール**（3章）：出勤は必須、休憩は開始・終了の両方か両方なし、日をまたぐ時刻は不可、未来の日・時刻は不可、今の記録と同じ内容は不可。申請中の申請がある日は、承認・却下されるまで新しい申請はできない（取り下げの機能は作らない。間違えた申請は、管理者に却下してもらう）。
4. **申請ウィンドウの空欄は「なし」**（2-1）：ウィンドウは今の値が入った状態で開き、空欄にした項目は「なし」として申請する（間違って記録された休憩を消すこともできる）。「申請」ボタンで選べる日は、表示中の月の日だけ。
5. **申請内容の表示**（2-3）：カレンダーに状態のバッジ（申請中を優先）、日付を押すと、その日の申請の一覧（変わった項目だけ「変更前 → 申請値」）。
