## 1. 目的

- メイン画面で、現在時刻（日本時間、秒まで）と、本日の出勤・退勤・休憩を表示する。
- 出勤・退勤・休憩開始・休憩終了のボタンで、**操作した時刻**を記録する（FR-003、BR-004）。
- 出勤・退勤を、同じ日に2回以上押したときは、すぐには記録せず、**上書き確認**を出す（BR-001）。
- 休憩は1日1回。**休憩終了のあとは「休憩開始」を押せなくする**（D-007、D-042）。
- 依頼者が、勤怠（`attendances`）の取得・登録（INSERT）・更新（UPDATE）を書く。
- 自動テスト（PHPUnit）を導入する（[技術方針.md](../技術方針.md) 2-4・2-5）。

この PR では作らないもの：簡単残業申請のボタン（PR 5）、ハンバーガーメニュー（行き先の「記録表示」ができる PR 4 で追加。承認・アカウント作成の項目は、それぞれの PR で追加）。

## 2. 画面と動き

画面モック（Main）の見た目に合わせる。PC とスマホの両方の幅で使えるようにする。

| 部分 | 内容 |

| 現在時刻 | 日付（例：2026年10月15日（木））と時刻（例：09:01:45）。1秒ごとに更新。**サーバーの時計に合わせて表示**する（パソコンの時計がずれていても、記録される時刻と表示がずれないようにする） |

### 2-1. 記録のしかた

- ボタンを押すと、画面は切り替えずに、JavaScript からサーバー（`api/attendance.php`）に送り、結果で画面を書き換える（[PHPコーディング方針.md](../PHPコーディング方針.md) 3-3 のとおり）。
- **記録する時刻は、サーバーが受け取った時刻**（パソコンの時計は使わない）。上書きの場合は、「上書きする」を押した時刻。
- **時刻は分単位で記録する（秒は切り捨て）**。例：09:01:45 に押したら 09:01:00。画面の表示（時:分）と、PR 4 の労働時間の計算を一致させるため。
- **勤務日は、押した日（0時で切り替え）**。
- 押してよいかの判断（3章）は、**サーバーで必ず行う**。画面のボタンの状態は、表示のためだけ（画面を2つ開いて操作した場合なども、サーバーで正しく止める）。
- 上書き確認も、サーバーが「すでに記録がある」と返したときに出す（判断をサーバーの1か所にまとめる）。

## 3. ボタンを押せる条件

| ボタン | 押せる条件 | 押したときの動き |
| --- | --- | --- |
| 出勤 | 出勤が未記録 | 本日の行を作って、出勤を記録（INSERT） |
|  | 出勤が記録済みで、**休憩・退勤がまだ** | 上書き確認 →「上書きする」で、出勤を今の時刻に更新（UPDATE） |
|  | 上記以外（休憩・退勤の記録がある） | 押せない（時刻の前後が逆になるため。間違いは修正申請（PR 5）で直す） |
| 退勤 | 出勤が記録済み、休憩中ではない、退勤が未記録 | 退勤を記録（UPDATE） |
|  | 退勤が記録済み | 上書き確認 →「上書きする」で、退勤を今の時刻に更新（UPDATE）（退勤のあとも仕事を続けた場合） |
| 休憩開始 | 出勤が記録済み、退勤が未記録、**休憩開始が未記録** | 休憩開始を記録（UPDATE）（1日1回。D-042） |
| 休憩終了 | 休憩中（休憩開始が記録済みで、休憩終了が未記録） | 休憩終了を記録（UPDATE） |

状態バッジ：出勤が無い＝未出勤／退勤がある＝退勤済み／休憩中＝休憩中／それ以外＝勤務中。

## 7. 確認したいこと（2026-10-15 すべて推奨どおりで承認。D-059・D-060）

1. **範囲と担当**（1章・4章）：依頼者が書くのは 5章の6つの関数でよいか。
2. **出勤の上書きは、休憩・退勤の前だけ**（3章）：画面モックでは、出勤はいつでも上書きできる。ただし、休憩や退勤のあとに出勤を上書きすると「出勤が休憩より後」のように時刻の前後が逆になるため、押せなくする案。間違いは修正申請（PR 5）で直す。
3. **勤務日は 0時で切り替え**（2-1）：0時をまたいで働いた場合、0時以降の退勤は押せない（その日の出勤が無いため）。修正申請で直す。標準の勤務時間（9:00〜18:00）では起きないため、今回はこの単純な形を推奨。
4. **時刻は分単位で記録（秒は切り捨て）**（2-1）。
5. **`bindParam` と `bindValue`**（[決定事項.md](../決定事項.md) の「未決定」）：6つの関数を書く前に、どちらに揃えるかを決めたい。どちらも安全。`bindValue` は値をそのまま渡せて、`bindParam` の「変数を参照で結びつける」注意が要らないため、Claude は `bindValue` を推奨（依頼者が PR 2 で使った書き方）。既存の `fetchWorkSettings()` は `bindParam` のままでよい（揃える場合は、依頼者が直す）。
