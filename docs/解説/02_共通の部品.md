# 2. 共通の部品

どの画面からも使う部品を説明する。ここが分かると、ほかのファイルが読みやすくなる。

## 2-1. `src/functions.php`：どこでも使う小さな関数

### `h()`：画面に出す値をエスケープする（XSS 対策）

```php
function h($value) {
    return htmlspecialchars((string) $value, ENT_QUOTES, 'UTF-8');
}
```

- 利用者が入力した値（氏名・理由など）をそのまま HTML に出すと、`<script>…</script>` が「文字」ではなく「プログラム」として動いてしまう（XSS：クロスサイトスクリプティング）。
- `htmlspecialchars()` は `<` を `&lt;` のように置き換えて、ブラウザに「ただの文字」として表示させる。`ENT_QUOTES` は `'` と `"` も置き換える指定（`value="…"` の中に出すときに必要）。
- `(string)` を付けているのは、`null` を空文字にするため（PHP 8.1 以降、`null` を渡すと非推奨の警告が出る）。
- **画面に出す値は、すべて `<?= h(…) ?>` で出す**。このシステムの PHP の画面は、例外なくこの形になっている。

### `appUrl()`：アプリの中の URL を作る

```php
appUrl('css/style.css')   // → '/attendance/css/style.css'（WSL の場合）
appUrl('')                // → '/attendance/'（メイン画面）
```

- アプリを置いた場所（`/var/www/html/attendance` なら `/attendance`）を、`$_SERVER['DOCUMENT_ROOT']` と、このファイルの場所から自動で計算して、先頭に付ける。
- そのため、Claude の検証環境（`/nm_attendance/`）でも WSL（`/attendance/`）でも、同じコードで正しい URL になる。

### `assetUrl()`：CSS・JS の URL を作る（キャッシュ対策。D-068）

```php
assetUrl('css/style.css')  // → '/attendance/css/style.css?v=1761100000'
```

- `appUrl()` の後ろに、ファイルを最後に変えた日時（`filemtime()`）を `?v=` で付ける。
- ブラウザは「同じ URL なら、前に読み込んだもの（キャッシュ）を使う」。ファイルが変わると数字が変わり、別の URL になるので、ブラウザが新しいファイルを読み込む。Ctrl＋F5 が要らなくなる。

### `redirect()`・`jsonResponse()`・`abort()`：応答を返して終わる

| 関数 | 使う場面 | すること |
| --- | --- | --- |
| `redirect('login.php')` | 画面を移すとき | `Location` ヘッダーを出して `exit` |
| `jsonResponse(200, [...])` | API の応答 | 状態コード・`Content-Type: application/json`・JSON を出して `exit` |
| `abort(403, '…')` | 権限が無いなど | 状態コードと短い文を出して `exit` |

どれも中で `exit` するので、呼んだところで処理が終わる。戻り値の型の `never` は「この関数からは戻ってこない」という印。そのため、`if` で囲んだあとに `else` を書かなくてよい。

## 2-2. `src/dbconnect.php`：DB に接続する（依頼者が書いた部分）

```php
$pdo = new PDO($dsn, $user, $pass, [
    PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,       // SQL のエラーを例外にする
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,  // 結果を ['列名' => 値] の形にする
    PDO::ATTR_EMULATE_PREPARES => false,               // SQL と値を DB 側で別々に扱わせる
]);
$pdo->exec("SET time_zone = '+09:00'");                // NOW() などを日本時間に
```

- この3つのオプションの意味は4章で詳しく説明する。
- 接続できなかったときは、エラーの中身を `error_log()` に記録し、画面には「データベースに接続できません。」だけを出す（パスワードなどの情報を画面に出さないため）。
- このファイルを読み込むと、変数 `$pdo` ができる。ほかのファイルは、これを関数に渡して使う（関数の1つ目の引数が、いつも `PDO $pdo`）。

## 2-3. `src/errors.php`：想定外のエラーの処理

```php
set_exception_handler(function (\Throwable $e) {
    error_log($e);                       // 詳しい内容はログへ
    http_response_code(500);
    exit('エラーが発生しました。時間をおいて、もう一度お試しください。');
});
```

- どこかで例外（`throw`）が起きて、だれも受け止めなかったときに、この関数が呼ばれる。
- 画面には定型の文だけを出し、詳しい内容（どのファイルの何行目で、何が起きたか）は Apache のエラーログ（WSL では `/var/log/apache2/error.log`）に記録する。中身を画面に出すと、攻撃の手がかりになるため。
- `src/dbconnect.php` の最初で読み込んでいるので、DB を使う画面では必ず有効になる。

> **想定内のエラー**（入力の誤り、同じ申請がある など）は、例外にせず、画面に分かりやすい文を返す。**想定外のエラー**（DB が止まった、プログラムの誤り）だけが、ここに来る。

## 2-4. `src/session.php`：セッションと CSRF 対策

### セッションとは

HTTP は「1回ずつの問い合わせ」で、前の問い合わせを覚えていない。そこで、ブラウザに **セッション ID**（推測できない長い文字列）を Cookie で持たせ、サーバー側でその ID に対応するデータ（だれがログインしているか など）を保存する。PHP では `$_SESSION` という配列に入れたものが、次の問い合わせでも使える。

### `startAppSession()`：セッションを始める

主な設定と、その理由：

| 設定 | 理由 |
| --- | --- |
| 保存場所をアプリ専用のフォルダにする | Ubuntu の標準の設定は、約24分で古いセッションを消す仕組みがあり、「2時間操作が無ければログアウト」を守れないため |
| `session.use_strict_mode = 1` | サーバーが発行していない ID を受け付けない（他人が決めた ID を使わせる攻撃を防ぐ） |
| Cookie の `httponly` | JavaScript から Cookie を読めなくする（XSS が起きても ID を盗まれにくい） |
| Cookie の `samesite = Lax` | ほかのサイトからの POST に Cookie を付けない（CSRF の対策の1つ） |
| 最後の操作から 2時間（`SESSION_IDLE_SECONDS`）で、ログイン状態を消す | 席を離れたときの対策（2026-10-13 依頼者承認） |

### CSRF 対策：`csrfToken()` と `requireValidCsrfToken()`

**CSRF（クロスサイト・リクエスト・フォージェリ）**：利用者がログインしたまま悪いサイトを開くと、そのサイトが勝手にこのシステムへ POST を送り、利用者になりすまして操作させる攻撃。

対策は「正しい画面から送られたものだけを受け付ける」こと。

1. 画面を出すときに、推測できない文字列（トークン）を作ってセッションに保存し、フォームや `data-csrf-token` に埋め込む（`csrfToken()`）。
2. POST を受け取ったら、送られてきたトークンとセッションのトークンを比べる。違えば 400 で止める（`requireValidCsrfToken()`）。
3. 悪いサイトは、このトークンを知ることができないので、正しい POST を作れない。

比べるときは `hash_equals()` を使う（文字列を比べる時間から、正しいトークンを推測されないようにする関数）。

### `setFlash()` と `takeFlash()`：1回だけ出す通知

「申請を受け付けました。」のように、**画面を読み込み直したあとに1回だけ**出したい文に使う。

```php
setFlash('申請を受け付けました。');   // 処理のあとにセッションに入れて、画面を移す
// …次の画面で…
$flash = takeFlash();                // 取り出す（取り出したら消える）
```

## 2-5. `templates/`：画面の上下の共通部分

| ファイル | 中身 |
| --- | --- |
| `header.php` | `<head>`（CSS の読み込み、フォント、アイコン）と、画面上部のヘッダー（メニューのボタン、アプリ名、ログイン中の人の名前、ログアウトのボタン） |
| `menu.php` | ハンバーガーメニュー。権限ごとに項目を出し分ける（社員：記録表示、管理者：＋承認、システム管理者：アカウント管理・部署・勤務設定） |
| `footer.php` | `</body></html>` だけ |

画面の PHP は、`$pageTitle`（画面の名前）と `$currentUser` を用意してから `include('templates/header.php')` する。ヘッダーの中では、それらの変数を使って表示を変えている。

> ログアウトのボタンも、`<form method="post">` と CSRF トークンで送る。ログアウトを GET（リンク）で受け付けると、悪いサイトに画像として埋め込まれただけで、ログアウトさせられてしまうため（`logout.php` は POST 以外を 405 で断る）。

## 試してみる

1. 開発者ツール（F12）の「アプリケーション」→「Cookie」で、`ATTENDANCE_SESSID` を見る。`HttpOnly` と `SameSite=Lax` に印が付いている。
2. 記録表示で申請を出したあと、画面を読み込み直す（F5）。「申請を受け付けました。」は2回目には出ない（`takeFlash()` で消えたため）。
