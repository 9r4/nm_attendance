# 6. 記録表示

主なファイル：`records/index.php`、`js/records.js`、`src/records.php`、`src/holidays.php`

## 6-1. 画面ができるまで（`records/index.php`）

1. 社員・管理者だけ（`requireRole`）。
2. 表示する月を決める（`resolveMonth()`）。URL の `?month=2026-09` を見る。
3. その月の勤怠（`fetchMonthlyAttendances()`）と申請（`fetchMonthlyRequests()`）を、まとめて読む。
4. `buildCalendar()` で、日〜土の7マス×週の形に並べ、出勤日数と総労働時間を数える。
5. 日付を押したときに出す内容を、JSON にして `data-days` に埋め込む（`js/records.js` が使う）。

> 日ごとに SQL を実行せず、**1か月分を1回の SQL で読んでから、PHP で日付ごとに振り分ける**。SQL を31回実行するより、ずっと速い。

## 6-2. 表示する月を決める（`resolveMonth()`）

```php
resolveMonth('2026-09', '2026-10-15', '2025-04-01')
// → ['month' => '2026-09', 'label' => '2026年9月', 'first' => '2026-09-01', 'last' => '2026-09-30',
//    'prev' => '2026-08', 'next' => '2026-10']
```

- 前の月は入社した月まで、次の月は今月まで（D-061）。範囲の外や、形の正しくない値（`?month=abc`）が来たら、今月にする。
- URL の値は利用者がいくらでも書き換えられるので、**正しい形かどうかを必ず確かめてから使う**（`preg_match` で `YYYY-MM` の形か、範囲内か）。
- 月末の日は `date('Y-m-t', …)` で求める（`t` は「その月の日数」）。

## 6-3. 1日の労働時間（`dailyWorkMinutes()`）

**労働時間 ＝ 退勤 − 出勤 − 昼休憩 − 休憩**（D-049・D-061）

決まり：

- 出勤か退勤が無い日は計算しない（`null`）ので、総労働時間には入れない。出勤日数は「出勤の記録がある日」を数えるので、退勤が無い日は数えるが、出勤が無い日は数えない。
- 昼休憩（勤務設定の 12:00〜13:00 など）と休憩は、**勤務していた時間と重なる部分だけ**引く。例：13:30 に出勤した日は、昼休憩を引かない。
- 休憩は、開始と終了の両方があるときだけ引く。
- 昼休憩と休憩が重なったら、重なった分は1回だけ引く。

計算のしかた（例：出勤 9:00、退勤 18:00、昼休憩 12:00〜13:00、休憩 12:30〜13:15）：

```
勤務        9:00 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 18:00
昼休憩               12:00 ━━━━━ 13:00
休憩                       12:30 ━━━━━━ 13:15
まとめると           12:00 ━━━━━━━━━━━━ 13:15   ← 1時間15分を引く
労働時間 = 9時間 − 1時間15分 = 7時間45分
```

1. 引く時間帯を、勤務の時間帯の中に切り詰める（`max`・`min`）。
2. 開始の早い順に並べる（`usort`）。
3. 前から順に、すでに数えた範囲（`$coveredUntil`）より後ろの部分だけを足していく。これで重なりを二重に数えない。

時刻は `strtotime()` で秒（1970年からの秒数）にして計算し、最後に `intdiv(…, 60)` で分にする。

> 承認済みの残業（`overtime_end_at`）は、計算に使わない。実際の退勤時刻で計算する（D-061）。

## 6-4. カレンダーの組み立て（`buildCalendar()`）

- 月の1日が何曜日か（`date('w', …)`。日曜が 0）を調べ、その数だけ空のマス（`null`）を先に入れる。
- 1日から月末まで、1日ずつ「その日のマス」を作る。マスには、日付・祝日の名前・休日か・今日か・出勤／退勤・労働時間・申請のバッジ・申請できるか、などを入れる。
- 最後に、7の倍数になるまで空のマスを足し、`array_chunk($cells, 7)` で週ごとに分ける。

### 申請のバッジ（`requestBadgeStatus()`）

その日の申請のうち、申請中が1つでもあれば「申請中」、無ければ一番新しい申請の状態（承認済み・却下）を出す。

## 6-5. 祝日の計算（`src/holidays.php`）

祝日は DB に持たず、法律のルールで計算している（D-044）。毎年、表を更新する手間が要らない。

1. **国民の祝日**：日付が決まっているもの（元日 1/1 など）、「第2月曜日」のもの（成人の日など。`nthMonday()`）、計算で決まるもの（春分の日・秋分の日。天文学の近似式）、年によって変わったもの（2020・2021 年のオリンピックの移動など）。
2. **振替休日**：祝日が日曜日なら、その後の最も近い「祝日でない日」が休み。
3. **国民の休日**：前の日と次の日が祝日で、その日自体は祝日でない日（例：敬老の日と秋分の日の間）。2007 年からは、土曜日・日曜日でも当てはまる。

計算できるのは 2000〜2099 年（春分・秋分の式が使える範囲。`HOLIDAYS_MIN_YEAR`・`HOLIDAYS_MAX_YEAR`）。

> 正しさは、内閣府の祝日の一覧を元にした公開データ（`holiday-jp/holiday_jp`）と、2000〜2050 年のすべての祝日・休日を突き合わせてテストしている（11章）。2019 年の即位の日など、法律で特別に決まった休日も入っている。

## 6-6. 日付を押したとき（`js/records.js`）

- PHP が埋め込んだ `data-days`（日付ごとの記録と申請）を `JSON.parse` で読み込んでおき、押された日のデータでウィンドウを作る。**サーバーに問い合わせないので、すぐ開く**。
- 記録も申請も無い日は、その日の申請ウィンドウをすぐ開く（D-051）。
- 申請の内容は、`document.createElement()` と `textContent` で組み立てる（`innerHTML` に文字をつなげて入れない）。`textContent` は中身をいつも「文字」として扱うので、理由に `<script>` が書かれていても動かない（XSS 対策の JavaScript 版）。
