# `src/errors.php` を読む（共通のエラー処理）

## このファイルの役割

**想定していなかったエラー（例外）が起きたときの、最後の受け皿**。どこで起きても、ここで受け止めて、詳しい内容はエラーログに残し、画面には決まった文（HTTP 500）だけを出す。

- 読み込まれるのは、`src/dbconnect.php` の中（DB を使う画面・API はすべてここを通る）と、DB を使わない `logout.php`。
- 14行だけの短いファイルだが、すべての画面の安全にかかわる。

## 全体の構成

| 行のあたり | 中身 |
| --- | --- |
| 5行 | エラーの内容を画面に出さない設定 |
| 7〜14行 | 受け止めなかった例外を処理する関数を登録する |

---

## 1. エラーを画面に出さない

```php
ini_set('display_errors', '0');
```

- `ini_set()`：PHP の設定（`php.ini` の値）を、このリクエストの間だけ変える。
- `display_errors` を `'0'` にすると、PHP の警告やエラーの文が画面に出なくなる。エラーの文には、ファイルのパスや SQL など、外の人に見せたくない情報が入ることがあるため。

## 2. 受け止めなかった例外の処理

```php
set_exception_handler(function (\Throwable $e) {
    error_log($e);
    if (!headers_sent()) {
        http_response_code(500);
        header('Content-Type: text/plain; charset=UTF-8');
    }
    exit('エラーが発生しました。時間をおいて、もう一度お試しください。');
});
```

- `set_exception_handler()`：どの `try … catch` でも受け止められなかった例外が出たとき、PHP が呼ぶ関数を登録する。
- `function (\Throwable $e) { … }`：名前の無い関数（無名関数・クロージャ）。登録するためだけの関数なので、名前を付けずにその場で書いている。
- `\Throwable`：例外（`Exception`）と、PHP 自体のエラー（`Error`。存在しない関数を呼んだ、型が合わない など）の、両方の親にあたる型。これで受けると、どちらも受け止められる。先頭の `\` は「PHP 標準の（名前空間の一番上の）`Throwable`」という意味。
- `error_log($e)`：例外を文字列にして、エラーログ（Apache のログなど）に書く。例外を文字列にすると、エラーの文に加えて、どのファイルの何行目で起きたか、どの関数から呼ばれたか（スタックトレース）が入る。調べるときは、ここを見る。
- `headers_sent()`：画面への出力が、もう始まっているか。HTML を途中まで出したあとで例外が起きた場合、HTTP の状態やヘッダーはもう変えられない。まだ始まっていないときだけ、500 と `text/plain` を設定する。
- 最後に、決まった文を出して終わる。

> **ここが重要**：このシステムでは、**SQL の1つ1つを `try … catch` で囲まない**。想定外のエラーは、すべてここに任せる（D-036）。`try … catch` を書くのは、「同じ申請が二重にある（一意制約の違反）」のように、エラーの種類ごとに画面で別の案内を出したい場所と、トランザクションだけ。あちこちで `catch` すると、コードが長くなるうえ、エラーを握りつぶして気付けなくなる原因になる。

## まとめ：このファイルから学べること

| 書き方 | このファイルでの例 |
| --- | --- |
| エラーの詳細は画面に出さない | `display_errors` を `'0'`、画面には決まった文 |
| 詳細はログに残す | `error_log($e)`（スタックトレースも入る） |
| 想定外のエラーは1か所で受ける | `set_exception_handler()` |
| 例外も PHP のエラーも受ける | `\Throwable` で受ける |
| 出力が始まっていたらヘッダーを触らない | `headers_sent()` で確かめる |
