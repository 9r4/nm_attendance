# 開発環境手順書（依頼者がコードを書いてプッシュする）

依頼者が、WSL の `/var/www/html/attendance` を、Windows の VS Code で開いてコードを書き、GitHub にプッシュするための手順（決定事項 D-046〜D-048）。

- 開発する場所：`/var/www/html/attendance`（確認用と同じフォルダ。保存して `http://localhost/attendance/` を開けば、すぐ確認できる）
- 編集：Windows の VS Code ＋「WSL」拡張（見た目は普通の VS Code のまま、WSL 内のファイルを編集できる）
- プッシュ：VS Code の GitHub ログインを使う（HTTPS）

## 表記のルール

**【ターミナルで実行】** は WSL のターミナル（または VS Code のターミナル）で実行する。コードブロックの中身は、そのままコピーして貼り付けられる。`＜…＞` の部分だけは、**貼り付けたあと、自分の値に書き換えてから** Enter を押す。**【出力例（入力しない）】** は結果の見本。

## 1. VS Code の準備（初回のみ・Windows）

1. Windows に VS Code を入れる（入っていれば不要）。
2. VS Code の拡張機能で「**WSL**」（発行元：Microsoft）を入れる。
3. VS Code の左下の「アカウント」から、**GitHub にサインイン**する。

## 2. フォルダを VS Code で開く（初回のみ）

WSL のターミナルで、次を実行する。VS Code が開き、左下に `WSL: Ubuntu` のように表示されれば、WSL 内のファイルを開いている。

**【ターミナルで実行】**

```bash
cd /var/www/html/attendance
code .
```

> `code: command not found` と出たら、1 の「WSL」拡張を入れたあと、WSL のターミナルを開き直す。

以降のターミナルの操作は、**VS Code のターミナル**（メニューの「ターミナル」→「新しいターミナル」）で行う。VS Code の GitHub ログインは、VS Code のターミナルと、VS Code の「ソース管理」画面で使われる。

> **`git init` は不要**（実行しない）。このフォルダは `git clone` で作ったので、すでに Git の管理下にある（`.git` フォルダがある）。確認は、ターミナルで `git status` を実行し、`On branch main` と表示されれば OK。
>
> `.gitignore` は、まだリポジトリに無い。実装 PR 1 で Claude が追加し、`git pull`（または作業ブランチへの切り替え）で入ってくる。自分で作る必要はない。

## 3. Git の初期設定（初回のみ）

コミットに記録される名前とメールアドレスを設定する。メールアドレスは、GitHub の Settings → Emails にある `…@users.noreply.github.com` の形を使うと、本当のアドレスを公開せずに済む。

**【ターミナルで実行】**（`＜…＞` を書き換えてから実行）

```bash
git config --global user.name "＜あなたの名前＞"
git config --global user.email "＜GitHub のメールアドレス＞"
```

## 4. 接続先を、プッシュできる形に変える（初回のみ）

いまの接続先（`git@github-nm:…`）は、**読み取り専用のデプロイキー**のため、プッシュできない。VS Code の GitHub ログインを使う HTTPS の接続先に変える。

**【ターミナルで実行】**

```bash
cd /var/www/html/attendance
git remote set-url origin https://github.com/9r4/nm_attendance.git
git remote -v
```

**【出力例（入力しない）】**

```
origin  https://github.com/9r4/nm_attendance.git (fetch)
origin  https://github.com/9r4/nm_attendance.git (push)
```

取得できるかを確認する（エラーが出なければ OK。初回は、VS Code が GitHub へのサインインを求めることがある）。

**【ターミナルで実行】**

```bash
git fetch origin
```

> プッシュできるかは、最初の作業（5章）で確認される。もし VS Code のログインが使われず、ユーザー名とパスワードを聞かれて失敗する場合は、7章（SSH 鍵を使う方法）に切り替える。
>
> デプロイキー（`github-nm`）は使わなくなるが、残しておいても害はない。不要なら、GitHub のリポジトリの Settings → Deploy keys で削除してよい。

## 5. いつもの作業の流れ（機能ごと）

Claude が作業ブランチに「枠」をプッシュしたら、そのブランチ名（例：`claude/xxx`）が伝えられる。

### 5-0. GitHub と手元の、最新の状況を確認する

まず `git fetch` で、GitHub の最新の状況を取ってくる（手元のファイルは変わらない）。そのあと `git status` で、手元と GitHub の差を見る。

**【ターミナルで実行】**

```bash
cd /var/www/html/attendance
git fetch origin
git status
```

| `git status` の表示 | 意味 | すること |
| --- | --- | --- |
| `Your branch is up to date with 'origin/…'` | 手元と GitHub が同じ | なし |
| `Your branch is behind 'origin/…' by N commits` | GitHub の方が新しい（Claude などが更新した） | `git pull` で取り込む |
| `Your branch is ahead of 'origin/…' by N commits` | 手元にだけコミットがある（まだプッシュしていない） | `git push` |
| `… have diverged` | 両方に別々のコミットがある | `git pull` してから `git push`（うまくいかなければ Claude に相談） |
| `Changes not staged for commit` ／ `Untracked files` | 保存したが、まだコミットしていないファイルがある | 必要なら `git add` → `git commit` |

> `git fetch` をしないと、`git status` は前回取ってきた時点の情報で比べるため、「同じ」と表示されることがある。

詳しく見たいときは、次のコマンドを使う。

**【ターミナルで実行】**

```bash
git log --oneline HEAD..@{u}
git log --oneline @{u}..HEAD
git branch -r
```

- 1つ目：GitHub にあって、手元に無いコミット（`git pull` で入ってくるもの）。
- 2つ目：手元にあって、GitHub に無いコミット（`git push` で上がるもの）。
- 3つ目：GitHub にあるブランチの一覧（Claude が作った作業ブランチも、ここに出る）。

### 5-1. 作業ブランチに切り替える

**【ターミナルで実行】**（`＜ブランチ名＞` を書き換えてから実行）

```bash
cd /var/www/html/attendance
git fetch origin
git switch ＜ブランチ名＞
```

**【出力例（入力しない）】**

```
branch 'claude/xxx' set up to track 'origin/claude/xxx'.
Switched to a new branch 'claude/xxx'
```

> 切り替えると、`http://localhost/attendance/` の表示も、そのブランチの内容に変わる。

### 5-2. コードを書いて、ブラウザで確認する

VS Code で `TODO` の部分を書き、保存して、ブラウザで `http://localhost/attendance/` を開いて確認する。

### 5-3. コミットしてプッシュする

VS Code の「ソース管理」画面でも行える。ターミナルで行う場合は、次のとおり（`＜…＞` を書き換えてから実行）。

**【ターミナルで実行】**

```bash
git add ＜変更したファイル＞
git commit -m "＜何をしたか（日本語）＞"
git push
```

- コミットメッセージに、`Co-Authored-By:` などのクレジット表記は付けない（運用ルール6章）。
- `main` には直接コミットしない。必ず作業ブランチで行う。
- プッシュしたら、Claude に伝える。Claude がテストとレビューを行い、PR を作る（または更新する）。

### 5-4. PR がマージされたあと（片付け）

PR がマージされると、GitHub 上の作業ブランチは自動で削除される。手元も `main` に戻して、最新にし、作業ブランチを削除する（`＜ブランチ名＞` を書き換えてから実行）。

**【ターミナルで実行】**

```bash
git switch main
git pull
git fetch --prune
git branch -D ＜ブランチ名＞
```

> スカッシュマージのため、`git branch -d`（小文字）では「マージされていない」と表示されて削除できない。`-D`（大文字）を使う。マージ済みの内容は `main` に入っているので、消して問題ない。

## 6. 注意

- `docs/` と `CLAUDE.md` は、この場所には無い（sparse-checkout で除外している）。ドキュメントは GitHub 上で読む。
- `src/dbconnect.php` には、DB のパスワードを直接書く（D-045）。**リポジトリは公開しない。**
- 作業ブランチにいる間に、Claude が同じブランチにプッシュすることがある。プッシュの前に `git pull` を実行すると、Claude の変更を取り込める（同じ行を変更していなければ、自動で取り込まれる）。

## 6-2. 自分だけのテスト用ファイルを、Git に無視させる

自分の確認用に作ったファイル（例：`test.php`）を、コミットの対象にしたくない場合は、**`.git/info/exclude`** に書く。書き方は `.gitignore` と同じだが、**自分の環境だけで効き、GitHub には上がらない**。

VS Code で開いて編集する。

**【ターミナルで実行】**

```bash
cd /var/www/html/attendance
code .git/info/exclude
```

ファイルの最後に、無視したいファイル名のパターンを1行ずつ書いて、保存する。例（リポジトリ直下の `test` で始まる `.php` ファイルを無視する）：

**【書き加える内容】**

```
/test*.php
```

- 先頭の `/` は「リポジトリ直下だけ」という意味。`*` は「何文字でも」。
- **`/test*` や `test*` とは書かない**。自動テストのフォルダ `tests/`（PR で追加予定）まで無視されてしまう（Claude の環境で確認済み）。
- 確認は `git status`。無視したファイルが表示されなければ OK。

> チーム全体（リポジトリ）で無視するファイルは、`.gitignore` に書く。`.gitignore` の変更は、ソースの変更として PR で行う（Claude に依頼する）。

## 7. VS Code のログインが使えない場合（SSH 鍵を使う方法）

あなたの GitHub アカウントに、**書き込みもできる SSH 鍵**を登録する。

**【ターミナルで実行】**

```bash
ssh-keygen -t ed25519 -f ~/.ssh/github_account -C "wsl-github-account"
cat ~/.ssh/github_account.pub
```

表示された `ssh-ed25519 …` の1行を、GitHub の **アカウントの** Settings → **SSH and GPG keys** → **New SSH key** に登録する（リポジトリの Deploy keys ではない）。パスフレーズは、空でもよい（設定すると、プッシュのたびに入力が必要）。

**【ターミナルで実行】**

```bash
cat >> ~/.ssh/config <<'EOF'
Host github-account
  HostName github.com
  User git
  IdentityFile ~/.ssh/github_account
  IdentitiesOnly yes
EOF
cd /var/www/html/attendance
git remote set-url origin git@github-account:9r4/nm_attendance.git
ssh -T github-account
```

`Hi ＜あなたの GitHub ユーザー名＞! You've successfully authenticated…` と表示されれば成功（初回は `yes` と入力する）。

## 8. よくある失敗

| 症状 | 原因・対処 |
| --- | --- |
| `ERROR: The key you are authenticating with has been marked as read only.` | 接続先がデプロイキーのまま。4章を実行する |
| `Authentication failed` ／ `Password authentication is not supported` | VS Code のログインが使われていない。VS Code のターミナルから実行しているか確認する。だめなら7章 |
| `fatal: invalid reference: ＜ブランチ名＞` | `git fetch origin` を実行していない、またはブランチ名の書き間違い |
| `error: Your local changes … would be overwritten` | 保存していない変更があるまま、ブランチを切り替えようとしている。先にコミットするか、`git stash` で退避する |
| `! [rejected] … (fetch first)` | Claude が同じブランチにプッシュしている。`git pull` してから、もう一度 `git push` |
| `Permission denied`（ファイルの保存時） | フォルダの所有者が違う。`sudo chown -R $USER:$USER /var/www/html/attendance` を実行する |
